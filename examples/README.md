# 개인정보 없는 합성 예시

[입력](synthetic-inputs.json)과 [평가 기록](synthetic-evaluations.json)은 대응하는 `case_id`와 `source_id`로 연결합니다. 원문, 문항, 공고와 사실은 모두 계약 검사용으로 새로 구성했습니다. 점수는 실제 AI 실행 결과가 아니며 `record_kind: synthetic-contract`, `model: null`로 표시했습니다. 기록의 날짜는 예시 작성일입니다.

| 사례 | 원본문항 | 상세 공고 | 품질 | 적합 | 평가한 점수/배점 | 총점 |
|---|---|---|---:|---:|---|---:|
| synthetic-case-001 | 있음 | 있음 | 48/60 | 32/40 | 80/100 | 80 |
| synthetic-case-002 | 없음 | 없음 | 48/60 | null | 48/60 | null |
| synthetic-case-003 | 있음 | 없음, 직무명만 있음 | 43/60 | null | 63/85 | null |

두 번째 사례는 사실 자료와 형식/분량 규칙도 없으므로 별도 상태가 확인 필요입니다. 원문이 사실 목록에 없다는 이유로 거짓 판정을 하지 않습니다. 세 번째 사례의 직무명 기반 의견은 비점수 보조 의견에만 둡니다. 이 세 사례는 평가 범위가 달라 총점을 직접 비교하지 않습니다.

`node tools/check.mjs`는 합성 원문 해시, 자료 ID, 짧은 원문 인용, 배점과 null 처리를 확인하고 잘못된 기록을 거부하는 사례도 검사합니다. JSON Schema 전체 검증을 실행하려면 [사용 안내](../README.md)의 Ajv 옵션을 사용합니다. 실제 모델 품질과 사용자 선호 보정은 이 검사 범위에 포함하지 않습니다.
