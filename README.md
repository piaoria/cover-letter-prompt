# 자기소개서 작성과 검수 기준

사용자와 대화하며 자기소개서를 쓰고 고치는 동안 확인한 기준을 버전 관리합니다. dot과 Gemini에서 같은 문서와 입력 자료를 사용합니다. 별도 AI API 서비스나 자동 합격 예측 도구는 아닙니다.

## 사용 순서

1. [채점 기준 v0.1](rubrics/scoring-v0.1.md)을 읽습니다. 작성 규칙과 사실 경계도 이 문서에 있습니다.
2. 작성할 때는 기준 문서와 [작성 프롬프트](prompts/write.md), 검수할 때는 기준 문서와 [검수 프롬프트](prompts/review.md)를 함께 대화에 붙입니다. 기준 문서가 없다면 모델은 내용을 추측하지 말고 요청해야 합니다.
3. 원본문항, 상세 공고, 확인된 사실과 시간 순서, 원문, 수정 범위, 형식과 글자 수 계산 규칙을 제공합니다. 없는 자료는 `null`로 둡니다. 회사 이름이나 직무명만으로 상세 공고를 대신하지 않습니다.
4. 초안을 검토하고 확인 질문에 답합니다. 이미 좋은 문장은 유지하고 필요한 부분만 수정합니다. 새로운 사실은 사용자가 확인한 뒤 반영합니다.
5. 검수 결과는 [평가 스키마](schemas/evaluation.schema.json)에 맞춰 로컬의 `private/` 또는 `evaluations/`에 저장합니다. 원문과 실제 평가 결과는 이 저장소에 커밋하지 않습니다.
6. 반복해서 확인된 선호를 일반 규칙으로 정리합니다. 기준 또는 프롬프트 버전을 올리고 [변경 이력](CHANGELOG.md)에 이유와 확인 범위를 남깁니다. 개인 사례를 공개 예시로 옮기지 않습니다.

## 입력 계약

아래 항목을 대화에 전달합니다. 실제 자료는 저장소 밖이나 gitignore로 제외한 폴더에서 관리합니다.

```text
case_id: 대화 내 사례 ID
source_id: 원문 출처 ID (배치에서도 고정)
question: {id, text} 또는 null
posting: {id, text} 또는 null (상세 업무와 요구 역량이 있는 공고)
role_title: 직무명 또는 null
facts: [{id, text, 확인 상태, 시간 순서}] 또는 null
original: 원문 그대로, 없으면 null
change_scope: 작성 / 맞춤법만 / 지정 구간 / 전체 재작성
target_passages: 지정 구간 또는 null
constraints: 제목, 단락, 분량 및 글자 수 계산 규칙 또는 null
```

분량 규칙에는 상한과 하한, 코드 포인트/UTF-16/문자소 단위, 공백, 제목, 줄바꿈 포함 여부, CRLF 처리, 제목과 본문 사이 구분자를 적습니다. 알려지지 않은 항목은 확인 필요로 남기고 글자 수를 추측하지 않습니다.

기계적으로 저장한 평가 기록의 원문 해시는 원문 문자열을 정규화하지 않고 UTF-8 바이트로 변환해 SHA-256을 계산합니다. 제목이 있다면 `original`에 제목과 구분자까지 명시하여 같은 문자열을 계속 사용합니다. 해시를 계산할 수 없으면 값을 꾸며내지 말고 저장 준비가 미완료임을 알립니다. 작성 결과를 평가할 때도 평가 대상 문자열과 출처 ID를 새로 고정합니다.

## 평가 기록과 비교

글 자체 품질은 60점, 지원 적합은 40점입니다. 각 항목은 0~5 정수 앵커로 판단하고 `앵커 / 5 * 가중치`로 환산합니다. 원본문항이나 상세 공고가 없으면 관련 점수는 `null`입니다. 평가한 점수의 합과 최대 배점만 표시하며 부분 점수를 100점으로 환산하지 않습니다. 전체 항목이 평가됐을 때만 총점이 존재합니다.

범위와 자료가 다른 글의 총점을 직접 비교하지 않습니다. 문항 ID, 출처 ID, 상세 공고 ID, 원문 해시와 버전을 함께 확인합니다. 같은 항목만 비교할 때도 동일 기준과 입력 조건임을 밝혀야 합니다. 모델이 바뀌면 점수 차이를 글의 변화라고 단정하지 않습니다.

형식/분량 위반, 사실 모순, 확인 필요는 점수와 별도 상태입니다. 높은 점수가 이 상태를 해제하지 않습니다. 스키마 검사는 기록 형식과 산식을 확인할 뿐 AI의 판단 품질이나 합격 가능성을 검증하지 않습니다.

## 공개 범위와 버전 관리

이 저장소에는 일반화된 프롬프트, 기준, 스키마와 개인정보 없는 합성 예시만 저장합니다. 실제 자기소개서, 이름, 연락처, 민감한 경력 자료, 비공개 점수, 인증정보는 커밋하지 않습니다. [.gitignore](.gitignore)는 실수 방지용이며 이미 추적 중인 파일까지 보호하지 않습니다. `git add -f`로 우회하지 않습니다. 커밋 전에 파일 목록과 diff를 직접 확인합니다. 저장소 공개 범위를 변경하거나 강제 push하지 않습니다.

v0.1은 미보정 초기 기준입니다. 기존 로컬 검수 도구에서 평가 계약과 최소 수정 원칙을 참고했으며, 기존 원문과 평가 파일은 복사하지 않았습니다. 기존 도구의 테스트 통과는 AI 품질 검증 완료를 뜻하지 않습니다. 제한된 두 쌍의 선호 정보만으로 보정 완료라고 판단하지 않습니다.

## 합성 예시 확인

[예시 안내](examples/README.md)에는 상세 자료가 있는 경우, 자료가 빠진 과거 글, 직무명만 있는 경우가 있습니다. 모든 원문과 점수는 계약 검사용 합성 데이터입니다. [검증 스크립트](tools/check.mjs)는 설치 없이 Node.js로 실행할 수 있습니다.

```powershell
node tools/check.mjs
git diff --check
git status --short
```

스크립트는 배점, null 처리, 해시, 근거 인용, 링크와 안전한 파일 목록을 확인합니다. 전체 JSON Schema 검증에는 외부에 설치된 Ajv 2020 모듈을 선택적으로 지정할 수 있습니다. 기본 검사가 스키마 전체 검증을 대체하지는 않습니다.

```powershell
node tools/check.mjs --ajv2020 '로컬 Ajv의 dist/2020.js 경로'
```
